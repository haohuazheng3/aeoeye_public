llms.txt is a Markdown file at yoursite.com/llms.txt that gives AI agents a short, curated index of your best pages. Jeremy Howard of Answer.AI proposed it on 3 September 2024 ([llmstxt.org](https://llmstxt.org/)). It points agents somewhere; it neither blocks nor permits anything.

Should you add one? Only if it is nearly free or your customers use coding agents. Google says its Search ignores these files, the crawler documentation from OpenAI, Anthropic and Perplexity never asks for one, and a server-log study of 137,210 domains found 97% of existing files went unread in May 2026 ([Ahrefs](https://ahrefs.com/blog/llmstxt-study/)). Fix crawl access and quotable content first.

## What is llms.txt, and what problem does it solve?

llms.txt is a proposed convention: one file that tells an AI agent which pages on your site are worth reading first. The proposal argues that HTML wraps content in navigation, ads and JavaScript, and that context windows are still too small for most whole websites ([llmstxt.org](https://llmstxt.org/)).

Version 2 of the proposal, modified on 10 August 2026, adds details that older guides miss:

- The file can sit at the root or at any subpath, covering the pages beneath it. `/docs/llms.txt` covers `/docs/`, and the most specific file wins.
- Pages can have Markdown twins, named `page.md` or `page.html.md`.
- Two link relations help agents find things: `rel="describedby"` points to the llms.txt file, and `rel="alternate" type="text/markdown"` points to a page's Markdown twin.

llms-full.txt is not part of the proposal. Documentation platforms such as [Mintlify](https://www.mintlify.com/docs/ai/llmstxt) generate it as one file holding the full text of every page. Think of llms.txt as the index and llms-full.txt as the dump.

## What does an llms.txt file look like?

Only one element is required: an H1 with the site's name. Everything else is convention: a blockquote summary, optional context, then H2 sections of [Markdown](https://en.wikipedia.org/wiki/Markdown) links with short notes. This illustrative file is for a fictional company.

```
  # Brightside Billing

  > Invoicing software for freelancers and small agencies. Sends invoices, tracks payments and reminds late payers. Prices are in US dollars.

  ## Docs
  - [Quickstart](https://example.com/docs/quickstart.md): Send a first invoice in five minutes
  - [API reference](https://example.com/docs/api.md): REST endpoints, authentication and rate limits

  ## Pricing
  - [Plans](https://example.com/pricing.md): What each plan includes and what it costs

  ## Optional
  - [Changelog](https://example.com/changelog.md): Release history
```

Write the blockquote as the sentence you would want an AI to repeat: category, audience and what is distinct, with no adjectives. Links under `## Optional` are, by convention, the ones an agent can skip when it needs less context.

## How is llms.txt different from robots.txt and sitemap.xml?

robots.txt says which URLs a crawler may fetch, sitemap.xml lists URLs for search engines to discover, and llms.txt suggests which pages an agent should read first. Only robots.txt is an internet standard ([RFC 9309](https://www.rfc-editor.org/rfc/rfc9309.html)), and even its rules are not access authorization.

| | robots.txt | sitemap.xml | llms.txt |
|---|---|---|---|
| Job | Tells crawlers what they may fetch | Lists URLs to discover | Points agents to pages worth reading first |
| Format | Plain-text rules | XML, up to 50,000 URLs per file | Markdown links with notes |
| Read by | Crawlers, before fetching | Search engines | Agents told or built to look for it |
| Status | Standards Track RFC | Protocol at [sitemaps.org](https://www.sitemaps.org/protocol.html) | Informal proposal |
| Can it block anything? | It requests, crawlers choose | No | No |

The proposal says a sitemap is no substitute: it usually exceeds a context window and rarely lists Markdown versions.

The classic failure is contradiction. In a 2026 SIGCOMM CCR measurement of about 4 million domains, nearly 19% of llms.txt files linked to content that robots.txt or ai.txt blocked ([HPI summary](https://hpi.de/en/article/paper-accepted-at-sigcomm-ccr/)). An agent that obeys robots.txt cannot follow your own recommendation.

## How many sites actually use llms.txt?

About half of the well-known sites we checked do; across the whole web it is far rarer. In AEOeye's crawler access study (October 2026, hub: [AI crawler directory](/blog/ai-crawler-user-agent-directory)), 173 of 330 checkable sites (52.4%) served a valid llms.txt:

- SaaS brands: 108 of 180 (60%)
- AI-visibility vendors: 27 of 41 (65.9%)
- E-commerce and consumer brands: 33 of 70 (47.1%)
- News publishers: 1 of 29 (3.4%)

Only 28 of 384 robots.txt files (7.3%) mention llms.txt at all. Treat these as a snapshot, not a market statistic: it is a convenience sample of established brands, fetched once on 3 October 2026, and a file counts only if `/llms.txt` returned 200, was not HTML and began with a Markdown H1. We cannot tell hand-written files from platform-generated ones ([per-site data](/resources/ai-crawler-access-study-2026-10.csv)).

The wider web looks different. A SIGCOMM CCR paper covering about 4 million Tranco-list domains found llms.txt on about 49,600, versus about 1.53 million with robots.txt, concentrated in tech and business sectors ([HPI summary](https://hpi.de/en/article/paper-accepted-at-sigcomm-ccr/)). Ahrefs found it on 28% of the domains in its analytics product and calls that an upper bound for a technical sample. Platforms also inflate counts: the proposal lists Wix, Mintlify, GitBook, Yoast SEO and AIOSEO as generating files automatically.

## Do AI engines actually read llms.txt?

Nothing documented says so for search. Google says Search ignores the file, OpenAI, Anthropic and Perplexity do not mention it in their crawler documentation, and logs show almost no AI search traffic fetching it. The readers that do show up are coding agents.

- **Google Search.** Google's generative AI guide, updated 10 July 2026, says you need no AI text files or Markdown to appear in Google Search, including AI features, because Search does not use them. Creating them for other systems will neither harm nor help your visibility ([Google Search Central](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide)).
- **Chrome.** Lighthouse's experimental agentic-browsing category has an optional llms.txt audit. It flags server errors and shows not applicable when the file returns 404. That is agent readiness, not ranking ([Chrome for Developers](https://developer.chrome.com/docs/lighthouse/agentic-browsing/llms-txt)).
- **OpenAI, Anthropic, Perplexity.** Their crawler pages explain robots.txt controls for [OpenAI](https://developers.openai.com/api/docs/bots), [Anthropic](https://support.claude.com/en/articles/8896518-does-anthropic-crawl-data-from-the-web-and-how-can-site-owners-block-the-crawler) and [Perplexity](https://docs.perplexity.ai/guides/bots) bots, with no llms.txt guidance. All three publish llms.txt for their own developer docs ([OpenAI](https://developers.openai.com/llms.txt), [Anthropic](https://platform.claude.com/llms.txt), [Perplexity](https://docs.perplexity.ai/llms.txt)). That shows documentation agents use it, not that their search bots read yours.
- **Server logs.** Ahrefs, an SEO software vendor, analyzed May 2026 traffic for 137,210 domains. Of the requests that reached llms.txt files, 96% came from bots, and AI retrieval bots such as OAI-SearchBot and PerplexityBot made about 1.1%. AI bots made zero requests for files that did not exist. Ahrefs stresses that fetched does not mean read.

GPTBot and Anthropic's Claude-Code were the most frequent named AI fetchers in those logs, and the proposal says the file is used most heavily for software documentation. If your product has docs or an API, that is your audience.

## Should your site have an llms.txt?

Add one if it is nearly free or your users run coding agents; otherwise it belongs behind crawl access and quotable content. It takes about an hour and Google says it cannot hurt Search visibility, but nothing shows it moves recommendations. Anyone promising citations from this file is selling a checkbox.

Add one if:

- You publish developer docs, an API or an SDK.
- Your platform generates one for you. Review it instead of writing it.
- You run a large structured knowledge base and can generate the file from the same source.

Skip it for now if you are a small local business or a thin marketing site. Your problem is whether the web describes you accurately, and an index of three marketing pages adds nothing. Also skip it if you would maintain it by hand: Ahrefs warns that a stale file misleads every agent that reads it.

Do these first. OpenAI says sites opted out of OAI-SearchBot are not shown in ChatGPT search answers ([OpenAI](https://developers.openai.com/api/docs/bots)), and Google says a page must be indexed and snippet-eligible to appear as a supporting link in AI Overviews or AI Mode ([Google](https://developers.google.com/search/docs/appearance/ai-features)). In our study, 24 of 88 e-commerce homepages (27.3%) challenged a self-identified crawler, so bot protection can lock you out without a robots.txt rule. See [what makes content quotable by AI](/answers/what-makes-content-quotable-by-ai).

If you do add one:

1. Open with a concrete one-sentence summary, then link only pages you want agents to read first, each with a plain note. Keep it small enough to fit in context.
2. Link clean pages, ideally Markdown twins, and check robots.txt allows every one.
3. Route agents to it with the `describedby` link or an HTTP Link header, and mention it in your docs. Ahrefs found AI tools fetch it when a link, index or instruction tells them it exists.
4. Generate it from your CMS or docs build, and treat it like code. Ahrefs reports researchers already probing llms.txt files for prompt injection, so keep instruction-like text out and review changes.
5. Test it: give an agent only your llms.txt, ask questions about your business, and check logs for `/llms.txt` requests after a month.
